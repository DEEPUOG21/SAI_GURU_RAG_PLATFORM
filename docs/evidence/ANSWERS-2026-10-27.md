# Answer quality, unknown facts and follow-up evaluation

Measured 27 October 2026: 60 frozen target questions per variant, plus 15 actual generated setup turns per variant. All **150 workflow executions completed**, with zero recorded failed workflow steps. Every setup and target answer was reviewed against written references and source documents by the coding agent, distinct from the generating model. This is not independent human annotation.

The four parts of this study are single-turn answer quality, safe abstention on missing company facts, follow-up understanding, and a controlled baseline-versus-current comparison including correctness, unsupported answers, false refusals, citations and workflow latency.

## Results

| Measurement | Dense baseline | Current hybrid + reranking |
| --- | ---: | ---: |
| Single-turn company-question correctness | 18 / 30 (60.00%) | 18 / 30 (60.00%) |
| Unknown-fact safe abstention | 15 / 15 (100%) | 15 / 15 (100%) |
| Follow-up target correctness | 14 / 15 (93.33%) | 14 / 15 (93.33%) |
| Both conversation turns correct | 13 / 15 (86.67%) | 13 / 15 (86.67%) |
| Overall target correctness | 47 / 60 (78.33%) | 47 / 60 (78.33%) |
| False refusals on answerable targets | 4 / 45 (8.89%) | 4 / 45 (8.89%) |
| Answers containing unsupported company factual substitutes | 7 / 57 (12.28%) | 7 / 57 (12.28%) |
| Citation-supported answers on source questions | 26 / 42 (61.90%) | 26 / 42 (61.90%) |
| Source questions routed to general knowledge | 16 / 42 | 16 / 42 |
| Workflow latency p50 | 2.99 s | 4.17 s |
| Workflow latency p95 | 7.68 s | 8.65 s |
| Completed target executions | 60 / 60 | 60 / 60 |

There is **no observed answer-correctness improvement** from reranking on this set. Every question's binary correctness outcome is identical between the two variants. The prior [retrieval comparison](RETRIEVAL-2026-10-27.md) measured improved section ranking; that does not by itself establish improved final answers.

## Main failure found: company-intent routing

All 13 incorrect target answers in each variant took the `DIRECT` route, bypassing document retrieval. Sixteen of the 42 source-answerable questions were routed this way; three still happened to return correct facts without source citations. Improving retrieval cannot repair a request that never reaches retrieval.

Concrete retained examples:

| Question | Actual answer problem | Available source fact |
| --- | --- | --- |
| List the four statuses in the Atlas task lifecycle in order. | Invented `Open, In Progress, Done, Archived`. | `Backlog, In Progress, Review, Done` in Product Documentation, Task workflow. |
| Who directs diagnosis and mitigation while an incident commander coordinates decisions? | Named an `Operations Section Chief`. | The technical lead, in Incident Response Policy, Incident roles. |
| What advance notice is needed for a request to work from another country? | Said the notice period was unspecified. | At least 15 calendar days and approval before travel, in Remote Work Policy, Location changes. |

The route classifier recognizes selected company terms but misses implicit policy/product intent in these phrasings. The study retains these failures rather than adding keywords while measurement is running. Follow-up rewriting often recovers the company context, but the deleted-Atlas-task conversation still fails. An emergency-leave setup answer fails even though its later follow-up succeeds, which is why pair-level accuracy is also reported.

The next implementation priority is source-aware routing for implicit company/product questions while preserving legitimate general-knowledge questions. After that fix, this set becomes regression/tuning evidence; validation of generalization requires another fresh, independently reviewed set.

## Protocol and metric definitions

- [Frozen 60-case questions, written reference answers and rubric](../../data/demo/answer-holdout.json), SHA-256 `62ee2c0355cff265621083f675a2dc8634433007531d437d553bbcb2f78ec1fa`. Thirty company-source questions, fifteen intentionally missing company facts, and fifteen follow-ups (twelve policy/product, two general knowledge, one user-provided codename). Actual generated setup answers, not ideal references, feed follow-up history.
- [All generated answers, citations, review labels/reasons, timings, node summaries and paired comparisons](answer-comparison.json). Scoped document/user identifiers and private credentials are excluded. Corpus and implementation hashes are retained; the indexed corpus was unchanged at completion.
- Both variants use Cloudflare `@cf/meta/llama-3.3-70b-instruct-fp8-fast`, temperature 0 and the same generation, grounding, guardrails, resolver and context budgets. Only retrieval changes: the process-local dense baseline disables lexical candidates and preserves dense order instead of reranking. Current runs use the unmodified hybrid/RRF/reranking workflow. No production settings or database records were changed.
- Cases and mode order are shuffled with a fixed seed. This is one observation per question/variant, not repeated quality sampling or a perfectly balanced crossover experiment. No result was regenerated to improve its score.
- **Correctness:** the answer must establish the reference facts needed for the question without a material contradiction. A correct general answer may earn correctness while lacking required citation coverage. Incomplete generic advice can fail correctness without being a fabricated company fact.
- **Unsupported-company-answer incidence:** any material factual substitute absent from or contradicted by company source facts, including generic substitutes used in place of the requested company fact. This is an answer-level flag, not an atomic-claim hallucination percentage. The denominator is 57 company targets, excluding three general/memory follow-ups.
- **Abstention:** the response declines or explicitly cannot establish the requested answer. Missing citations or a general-knowledge disclaimer alone are not automatically abstention. Unknown-safe abstention requires abstention with no unsupported company answer; false-refusal rate uses the 45 answerable targets.
- **Citation support:** all requested factual company claims have valid citations whose actual text supports them. Valid corroborating sections are accepted, not just exact expected section names. The denominator is 42 answerable source questions; abstentions do not earn citation coverage.
- **Latency:** measured workflow duration includes resolution, retrieval, authorization recheck, generation and verification. It excludes HTTP authentication, SSE transport, conversation persistence, session setup and the client-to-API network. These are not deployed browser response times or sustained-load measurements.

Coding-agent reviews used answer/citation packets with mode names omitted and identical answer/citation pairs grouped. Source-based reasons are published for every reviewed turn. This does not make the labels independent human ground truth; ambiguous paraphrases and completeness judgments warrant external review. The corpus and many underlying facts were already known during development; the questions were frozen for this diagnostic comparison, not drawn from an unseen real-world corpus.

Exploratory paired bootstrap intervals are in the raw evidence. Identical correctness outcomes produce a zero observed delta and zero-width empirical paired interval; this is not an equivalence test or proof of equal population performance. Latency comparisons are subject to provider load, caching and one-pass variability. Do not compare this semantic correctness percentage directly with the older eight-question lexical F1 score.

## Reproduce

With the existing private, restricted runtime connection and the matching indexed demo corpus:

```powershell
python scripts/benchmark_answers.py
```

The runner enforces read-only database transactions and the configured user's access scope. It checkpoints each turn under ignored `.local/deployment/`. `--resume` continues an interrupted run with matching corpus/configuration and no failed trials; failed trials remain recorded and require a distinct output for a fresh run. Do not overwrite failures or repeatedly retry for higher scores. Review all completed answers using the frozen rubric, attach explicit labels with `attach_reviews`, and publish only sanitized evidence.

Each review supplies `review_id`, boolean `correct`, `unsupported_claim` and `abstained`, boolean or N/A (`null`) `citation_supported`, and a source-based `reason`. The command below checks that every planned setup and target has exactly one review, recomputes cohort metrics and paired comparisons, and removes scoped resource IDs and trace outputs from the public copy without making inference or database calls:

```powershell
python scripts/benchmark_answers.py --reviews .local/deployment/answer-reviews.json --public-output docs/evidence/answer-comparison.json
```

Use `scripts/export_langsmith.py` with `--answer-mode dense_baseline` or `--answer-mode current`, distinct experiment names and output files. Preview is local by default; `--upload` sends the selected synthetic examples, answers and source-based review metrics to the configured workspace. All 60 target examples are shared between the variants. Subset metrics have their own eligible denominators; N/A citation support is not inserted as zero. Setup answers remain attached to the follow-up outputs. Imported timeline offsets are reconstructed from measured durations and labeled as such; LangSmith did not independently rescore these answers.

The experiments are in the existing [LangSmith answer-study dataset](https://smith.langchain.com/o/2a4a8185-3a71-4629-8b30-a89e91d915c3/a/-/datasets/a8cf4d02-1d4d-40f6-8c46-c6499a6c2205): `sai-guru-answer-dense_baseline-oct27-v1` and `sai-guru-answer-current-oct27-v1`. Workspace access is required. The generic `unsupported_claim` feedback averages all 60 targets; the explicitly named `unsupported_company_answer_rate` averages the 57 company questions used in this report. Likewise, unknown abstention, false refusals, follow-ups and citation support use 15, 45, 15 and 42 eligible examples respectively.

Readback verified 60 runs per experiment, zero recorded import-run errors, the same 60 reference examples, and all reported score values with their expected eligible sample counts. The private readback receipt retains these checks.

Backend regression checks: 253 passed, two skipped, one integration test deselected. The tests cover baseline isolation/restoration, frozen cohort validation, review completeness, eligible denominators, paired comparisons and shared LangSmith references. Existing application tests also passed; this does not substitute for independent browser, load or human-answer evaluation.
